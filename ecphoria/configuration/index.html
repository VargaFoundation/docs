Configuration

Ecphoria loads configuration from three sources, in order of precedence:

  1. Built-in defaults — sensible defaults for local development.
  2. ecphoria.toml — a file in the working directory.
  3. Environment variables — prefixed with ECPHORIA_, nested keys separated with __.

For example storage.data_dir is ECPHORIA_STORAGE__DATA_DIR, and embedding.provider is ECPHORIA_EMBEDDING__PROVIDER.

gateway.api_keysECPHORIA_GATEWAY__API_KEYSKeys, form <secret>@<tenant>:<role> (secret may be sha256:<hex>)

gateway.llm_proxy_enabledECPHORIA_GATEWAY__LLM_PROXY_ENABLEDfalseServe the OpenAI/Anthropic-compatible proxy at /v1/*

Embedding​

SettingEnv VarDefaultDescription
embedding.providerECPHORIA_EMBEDDING__PROVIDERnonenone, ollama or openai. none means BM25-only retrieval — set this to enable vector recall
embedding.modelECPHORIA_EMBEDDING__MODELnomic-embed-textModel name
embedding.dimensionECPHORIA_EMBEDDING__DIMENSION768Vector dimension — must match the model (nomic 768, bge-m3 1024)
embedding.batch_sizeECPHORIA_EMBEDDING__BATCH_SIZE64Texts per provider call on the bulk paths
embedding.ollama_urlECPHORIA_EMBEDDING__OLLAMA_URLhttp://localhost:11434Ollama server URL

An in-process ONNX embedding backend is available behind the embed-local build feature (no external service). A local cross-encoder reranker is behind rerank-local.

Memory — cognition​

The deterministic core (subject-based contradiction resolution, dedup, importance) is always on. LLM fact extraction and graph auto-population are opt-in.

SettingEnv VarDefaultDescription
memory.cognition.retrieval_vector_weightECPHORIA_MEMORY__COGNITION__RETRIEVAL_VECTOR_WEIGHT1.0Weight of the vector arm in the fusion. Set to 0.5 for a large corpus — see Knowledge base
memory.cognition.retrieval_lexical_weightECPHORIA_MEMORY__COGNITION__RETRIEVAL_LEXICAL_WEIGHT1.0Weight of the BM25 arm
memory.cognition.retrieval_scan_capECPHORIA_MEMORY__COGNITION__RETRIEVAL_SCAN_CAP2048Ranked candidates carried forward per query. Not a cap on how much of the corpus is searched — the lexical arm uses an inverted index over the whole scope
memory.cognition.graph_expansionECPHORIA_MEMORY__COGNITION__GRAPH_EXPANSIONfalseQuery-time knowledge-graph expansion
memory.cognition.extractionECPHORIA_MEMORY__COGNITION__EXTRACTIONnoneremember fact extraction: none or llm
memory.cognition.dedup_thresholdECPHORIA_MEMORY__COGNITION__DEDUP_THRESHOLD0.92Cosine similarity at/above which a new memory merges into an existing one
memory.cognition.decay_half_life_daysECPHORIA_MEMORY__COGNITION__DECAY_HALF_LIFE_DAYS30Half-life for importance decay, measured from when a memory was last touched
memory.cognition.decay_interval_secsECPHORIA_MEMORY__COGNITION__DECAY_INTERVAL_SECS0Background forgetting interval (0 = off)

Memory — promotion (webhooks → memories)​

Webhook deliveries land in episodic memory, which is SQL-queryable but invisible to search_memory. Promotion additionally writes the events that mark a durable outcome — merged pull requests, closed issues, resolved incidents — as memories, so they are recallable alongside documentation. Off by default: it changes what a corpus contains.

SettingEnv VarDefaultDescription
memory.promotion.enabledECPHORIA_MEMORY__PROMOTION__ENABLEDfalseWrite matching webhook events as memories too
memory.promotion.rulesECPHORIA_MEMORY__PROMOTION__RULEScloses/merges/resolutions"<vendor>:<event_type>"; * allowed on either side, and a trailing * on the type matches by prefix

Secrets​

Any secret setting also supports the _FILE convention — point ECPHORIA_CLUSTER__SECRET_FILE at a mounted file instead of passing the value inline, for Docker/Kubernetes secrets.

Distributed tracing (OTLP)​

Metrics ship to Prometheus at /metrics out of the box. To export traces, build with the otlp feature and set ECPHORIA_OTLP_ENDPOINT to your OTLP/HTTP collector (e.g. http://otel-collector:4318/v1/traces).
