Install the CLI

The choregos command drives your instance from a terminal or a script: projects, workflows, work items, tokens, applications, the A2A door, plugins. It calls the same API as the console, with your rights.

What you will be able to do: install the CLI, check what you downloaded, sign in to your instance, and keep the CLI at your instance's version.

Before you start: the address of your Choregos instance (here https://choregos.example.com) and an account on it.

From your instance​

Available from the release that follows 0.25.3

The downloads served by the instance, the install scripts and choregos self update arrive with the release that follows 0.25.3. On 0.25.3 and earlier, install from the GitHub release (below).

Your instance serves the CLI built for its own version, as a single native file for Linux, macOS and Windows: no Python is needed. The console's Integrations page, tab CLI, shows the commands below with your instance's address filled in.

Linux and macOS:

curl -fsSL https://choregos.example.com/cli/install.sh | sh

Windows (PowerShell):

irm https://choregos.example.com/cli/install.ps1 | iex

The script picks the file for your system, checks its SHA-256 against the instance's manifest, and puts choregos on your path.

By hand, download the file for your system from your instance:

SystemFile
Linux, x86-64choregos-linux-x86_64
Linux, ARM64choregos-linux-arm64
macOS, Apple siliconchoregos-macos-arm64
macOS, Intelchoregos-macos-x86_64
Windows, x86-64choregos-windows-x86_64.exe
curl -fsSLO https://choregos.example.com/downloads/cli/choregos-linux-x86_64
curl -fsSL https://choregos.example.com/downloads/cli/manifest.json

manifest.json gives the version and, for each file, its system, architecture, size and sha256. Compare it with the file you downloaded:

sha256sum choregos-linux-x86_64
chmod +x choregos-linux-x86_64 && mv choregos-linux-x86_64 ~/.local/bin/choregos

On macOS, shasum -a 256 gives the same digest. The same files, a SHA256SUMS file and their signatures are also attached to each GitHub release, under the same names.

An instance built without the CLI says so on its Integrations page; ask your operator, or use the GitHub release.

Keep it at your instance's version​

The CLI tells you when its version differs from your instance's. Replace it with the instance's own build:

choregos self update

From the GitHub release​

This works on every version, and is the way on 0.25.3 and earlier. It needs Python 3.12 and uv. Download three wheels of your instance's version from its GitHub release (here 0.26.1): choregos_cli-0.26.1-py3-none-any.whl, choregos_core-0.26.1-py3-none-any.whl and choregos_contracts-0.26.1-py3-none-any.whl. Then:

uv tool install --python 3.12 ./choregos_cli-0.26.1-py3-none-any.whl \
  --with ./choregos_core-0.26.1-py3-none-any.whl --with ./choregos_contracts-0.26.1-py3-none-any.whl

To upgrade, install the next version's wheels the same way with --force.

Sign in​

The CLI cannot issue its first token: create a full-access token in the console, menu under your name, My account, Access tokens, Create an API token (90 days). Then:

choregos login --api-url https://choregos.example.com --token chg_... --org acme
choregos whoami

What you should see: whoami prints who you are and your roles. The profile is saved in ~/.config/choregos/config.json (CHOREGOS_CONFIG names another file). Without a profile, the CLI reads CHOREGOS_API_URL, CHOREGOS_TOKEN and CHOREGOS_ORG, which suits a CI job.
